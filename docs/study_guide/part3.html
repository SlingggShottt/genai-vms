5. The GenAI machinery

Chapter 4 was the plumbing that produces structured facts. This chapter is where the generative AI comes in: one gateway that every model call passes through, and four features built on it.

5.1 The LLM gateway — one switchboard for every model

No service ever says "call model X". It says "do task event_verify". The gateway looks the task up in config/models.yaml, finds the model for the active profile, and handles everything around the call.

ProfileMeaning
localEverything on this machine through Ollama: vision tasks on qwen2.5vl:3b, text tasks on qwen2.5:3b. Default for development.
hybridVision stays local; text reasoning (query planning, reranking, reports, assistant, daily narrative) goes to cloud models (Gemini / Groq free tiers).
cloudEverything in the cloud (for a server with no GPU).

The tasks are: event_verify, jit_vqa, query_decompose, rerank, phase_tg, phase_vr, incident_synthesis, assistant, daily_narrative (and an evaluation judge).

What the gateway does on every call

  1. Cache check (Redis): an identical question gets the stored answer. Only for tasks where that is safe.
  2. Wait for the GPU chair (the lease, below).
  3. Call the model with a timeout. If it fails, try the next model in the fallback list.
  4. Validate the answer shape. We ask for JSON that must fit a Python schema (Pydantic). If it does not fit, the gateway shows the model its own mistakes and asks again (up to 2 more times).
  5. Record provenance: which provider and model answered, how many tries, whether a fallback was used. Reports store this.
Think of it as…A switchboard operator. You ask for "the doctor" (a task); the operator knows which doctor is on duty today (the profile), dials them, and if nobody picks up, tries the next one. And there is only one consulting room (the GPU): one doctor at a time.

The GPU lease (ADR-007)

A 4 GB card cannot hold the text model and the vision model at once without thrashing. A lease in Redis says which model family currently holds the GPU. Calls of the same family share it; a call of a different family waits its turn (and goes first in line so it is not starved). The lease expires if the holder crashes. We recently added a safety net: even a stuck holder stops being renewed after 15 minutes. (We found that bug the hard way during a benchmark; see chapter 10.)

What to say"Models are configuration, not code. Switching from local to cloud is one environment variable, and every answer records which model produced it."

5.2 Search — "find it in plain words"

Walking through one query

Query: "a person in a red top near the service door"

  1. Plan. In fast mode a keyword plan is enough (category = person, colour = red, zone = service door, time words like "yesterday"). In reason mode a language model decomposes the sentence into entities, relations, and sub-questions; relative times are resolved with the current time and the site's timezone.
  2. Encode. SigLIP 2 turns the text into a vector on the CPU (so the GPU stays free).
  3. Retrieve. The vector is compared with picture vectors of frames and tracks in Qdrant, with hard filters (camera, time, object type); event captions are searched in Postgres; the knowledge index is searched by meaning and by words. Colour and zone boost a result rather than filter it (the colour naming is rough).
  4. Fuse. Reciprocal Rank Fusion merges the ranked lists (figure 5.3); hits within 10 seconds on one camera become one window; the best 30 windows are kept.
  5. Rerank (reason mode). For the top 10 windows the system builds a short text excerpt of the digital twin ("a person, red top, in service-door zone, seen 14 times, speed 0.02") and asks a language model, five windows per call, for a score 0 to 1, a one-sentence reason, and the sub-questions it cannot answer from records. Final score = 40% fused + 60% model score.
  6. JIT refinement (optional "Look closer"). If the reranker said "cannot tell whether the bag is blue", a vision model looks at that keyframe and answers yes/no/unsure. Answers are cached, fed back for rescoring, and a "yes" is also written into the knowledge index so a later search can find the footage without asking again.

Other ways to search

  • Search by image: upload a photo; it is embedded and matched against tracked objects.
  • Find similar: draw a box on any frame (a result, an event keyframe, or the paused playback frame). The server cuts that part out of the stored keyframe and searches with it. built; browser check pending
  • Masks: for a result, SAM 2.1-tiny draws the outline of the matched object over the picture (computed once, cached).
Think of it as…Fast mode is a good librarian grabbing the books whose covers look right. Reason mode is the librarian then reading the blurbs of the ten best candidates and ranking them by how well they really fit. JIT is going back to open the book at one page to check a detail.
Numbers to knowFast mode: about 0.22 s median (0.25 s at the 95th percentile). Reason mode: about 15.5 s on this laptop (almost all of it the rerank). Cold object masks: 1.3 s; cached: 9 ms.
Be honest about…Search separates what is in the picture (phone, laptop, bike, trunk) far better than what is happening (turning left, handing over an object). A single frame cannot show motion. And a clean 4-way ablation (embedding only, +filters, +rerank, +JIT) is built but the final clean run was not completed; use the earlier results in chapter 9.

5.3 Reasoning — phases, evidence and the incident report

The steps in plain words

  1. A job is queued in a Postgres table (claimed with FOR UPDATE SKIP LOCKED, so two workers never take the same job; a worker that dies loses its lease and the job is claimed again).
  2. Phase location (TG = temporal grounding). Five frames from the primary camera are shown to the vision model: "which of the five phases is each frame?" The answers become spans on a timeline; impossible answers (going backwards in time) are repaired or rejected, and then the detector's own timing is used instead.
  3. Evidence (PhaVR = phase-specific captioning and VQA). For each phase and each camera, two frames and a few event-specific questions from a question bank (e.g. "is the area lit?") are shown; the answers are checked against the allowed vocabulary and become evidence items with stable ids such as ev-cap-03. The cited frames are copied to a separate bucket so they outlive the keyframe retention.
  4. Report. Two schema-checked LLM calls write stage summaries, then the causal chain, factors and recommended actions. Every claim must cite evidence ids that exist; bad citations are quoted back to the model for a retry; a claim that still cites nothing is dropped and counted. A tolerance exists for near-misses like [ev-cap-1].
  5. Store and announce. The report goes into Postgres and a PDF into MinIO; a JSON copy is kept; browsers get a live "report ready" push. Provenance says which model located the phases ("adapter", "zero-shot" or "rules"), per-step timings, and how many views were skipped.
Think of it as…A junior analyst: first marks on a timeline "the trouble started here", then sits with each camera's footage for each stage and takes notes with photo references, then writes the report with footnotes to those notes. A supervisor (the checker) strikes out any sentence without a footnote.
The one-line principleEvidence or it didn't happen. That is how we handle AI "hallucination": the model is not allowed to assert something that it cannot point at.
Be honest about…The default phase locator is the untrained vision model, and the model that reads each phase is also untrained: the second fine-tuned adapter (PhaVR) was never trained because it needs caption annotations nobody had time to make. If any model fails, the system falls back to the detector's own timing, and says so in the report's provenance.

5.4 The assistant — ask in chat

Examples the assistant handles: "What happened today?", "How many people were on cam01 yesterday?", "List high-severity incidents", "Show me the daily security report for yesterday", "Find a white car near the gate". A small model computes dates badly, so questions with clear keywords are routed to the right tool without asking the model; the rest go to a planner that returns a JSON action (at most 4 lookups). The conversation keeps the last 12 messages and a rolling summary.

Think of it as…A receptionist with seven filing cabinets (the tools). You ask a question; the receptionist pulls the right folder, reads you what is in it, and adds only a short explanation. If the folder is empty, the receptionist says "I found nothing", never "I think it was probably...".
What to say"The assistant never writes database queries. It can only call seven fixed, parameterised tools. And every answer is built from what those tools returned, with citation chips you can click."

5.5 Daily reports, the timeline and cases

  • Daily security report. A fixed set of SQL queries produces the day's facts (counts by type, camera, hour; incidents; alert response times). An LLM writes a short narrative from those figures; a post-check demands that every number in the text appears in the facts (one retry, then a template text, and the report says which was used). It is generated automatically after 06:00 site time for the previous day, or on demand for up to 7 days, and exported as a PDF.
  • Investigation timeline. One lane per camera showing events and incident reports across a period; events linked across cameras are outlined and shown on a "Linked" row. Drag across a lane to pick a period, then zoom, open the recording, play several cameras in sync from one playhead (measured drift well under 300 ms), save to a case, or search in that range.
  • Cases. Bookmark events, incident reports, footage moments and searches into an investigation with notes.

6. The AI ideas you need

You do not have to be an AI expert. You need about a dozen ideas, each explained with a picture in your head.

IdeaIn one sentenceEveryday picture
Object detection (YOLO)A model that looks at a picture and draws boxes around things with labels ("person", "car", "backpack").A spot-the-objects robot that circles things in a photo.
Tracking (ByteTrack)Gives the same object the same id in consecutive frames.Putting a name tag on every person in a crowd and following the tags.
EmbeddingA list of numbers (a vector) that captures the meaning of a picture or sentence, so similar things get similar numbers.GPS coordinates on a map of meaning: "red jacket" and "scarlet coat" are neighbours; "banana" is far away.
Vector searchFind the stored vectors closest to the query vector."Who lives nearest to this point on the map?"
SigLIP 2A model that makes embeddings for both text and images in the same space, so a sentence can find a picture.A translator that puts words and photos on the same map.
Hybrid search + RRFCombine search by meaning (dense) with search by exact words (BM25), then merge the rankings.Asking two friends for recommendations and trusting the places both name.
LLM / VLMLarge language model = reads and writes text. Vision-language model = also sees pictures.A reader vs. a reader with eyes.
Token & context windowModels read in word-pieces (tokens). The context window is how many fit at once. In our setup one image costs about a thousand tokens.The model's short-term memory.
Quantization (4-bit)Storing a model's numbers with fewer bits so it fits in memory.Saving a photo as a smaller JPEG: a little quality lost, a lot of space saved.
Zero-shot vs. fine-tuningZero-shot = ask a general model straight away. Fine-tuning = further train it on your examples.Asking a bright stranger vs. training a new hire.
LoRA / QLoRAFine-tune by training only a small add-on and leaving the big model frozen (Q = also squeezed to 4 bits).Clipping sticky notes onto a textbook instead of rewriting it.
Structured outputMake the model fill a form (JSON that fits a schema) and check it.A tick-box form, not an essay.
Hallucination & groundingModels sometimes state things that are not true. Grounding = tie every statement to evidence.Footnotes. No footnote, no sentence.

MeasureMeaningPicture
